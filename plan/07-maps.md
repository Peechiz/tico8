# 07 — Maps

## Demo

`examples/07-maps` has a room wider than the screen in `maps/room1.json`,
with `ground`, `walls`, `front` and `markers` layers, and a tileset with a
flags file beside it. The figure starts on the `spawn` marker tile, walks
with the directions, is stopped by `solid` tiles, and passes behind the
tiles of `front`. A camera follows it. Saving the map file or the flags
file changes the room in the running game without a restart.

## Spec

`01-spec.md`: Maps, Sprites, Positions and vectors.
`00-outline.md`: step 3, and "What reload means" in step 2.

## Decided

- **Not Tiled's files.** Maps are tico8's own JSON. Importing from Tiled is
  an optional enhancement.
- **A map file is `maps/<name>.json`:** the tileset's name and the layers
  by name, a layer being a list of rows, a row one line of text.
- **Flags live beside the tileset,** in `sprites/<tileset>.flags.json`, as
  flag name to the list of tiles that have it. Not in the map file: a flag
  is true of a tile in every map that uses the tileset.
- **Layer and flag names are typed by inference** from the JSON. The
  generated `maps.ts` imports both files and hands them to `map`.

## Layout

```
packages/tico8/src/maps/types.ts    what a game reads, and the two files' shapes
packages/tico8/src/maps/file.ts     a map file read into cells, and written back
packages/tico8/src/maps/flags.ts    a flags file read into sets of tiles
packages/tico8/src/maps/layers.ts   a map and its layers over cells, a sheet and a screen
packages/tico8/src/assets/maps.ts   the console's maps by address, live swap, restore
packages/tico8/src/vite/maps.ts     the generated maps.ts
packages/tico8/src/vite/assets-hmr.ts  tells the page a map or flags file changed
```

How a map reaches a game: the dev tool writes `maps.ts`, which imports each
map's JSON and its tileset's flags JSON and calls `map` from `tico8/assets`
with them and the tileset's sheet. The JSON is there when the module runs,
so a map is whole before `init`; only the tileset's picture loads. When
either file is saved the dev tool stops Vite restarting the game and tells
the page, which fetches the file again and swaps it into the map the game
already holds.

The generated file, exactly:

```ts
// Generated by tico8 from the maps folder. Do not edit.
import { map } from 'tico8/assets'
import room1_map from './maps/room1.json'
import { tiles } from './sprites'
import tiles_flags from './sprites/tiles.flags.json'

export const room1 = map({
  url: '/maps/room1.json',
  data: room1_map,
  tiles,
  flags: { url: '/sprites/tiles.flags.json', data: tiles_flags },
})
```

## Tasks

- [x] **1. Contract** *(contract)*. Lead. The shapes of the two files;
  `Tile`, `PlacedTile`, `Layer` and `TileMap`; `MapData` and `FlagData`
  that the parsers hand to the layers; the signature of every file below;
  the two events the dev tool sends.
  Owns: `src/maps/types.ts`, `src/assets/event.ts`, the declarations in
  every file below. Waits on: none.
- [x] **2. Map file.** `parseMap` turns the JSON into cells, refusing by
  reason a file that is not the right shape: a row of the wrong width, a
  layer of the wrong height, a tile that is not a number or `.`, a layer
  name that cannot be used. `writeMap` gives back the text of the file with
  its columns lined up, and `parseMap` of that text gives the same cells.
  Owns: `src/maps/file.ts`, `src/maps/file.test.ts`. Waits on: 1.
- [x] **3. Flags file.** `parseFlags` turns the JSON into a set of tiles
  for each flag, refusing by reason a flag name that cannot be used or a
  tile that is not a whole number from 0.
  Owns: `src/maps/flags.ts`, `src/maps/flags.test.ts`. Waits on: 1.
- [x] **4. Layers.** `createMap`: a layer draws its tiles through the
  sheet, only those the clip can show, moved by the camera; `tile` reads a
  cell and its flags and `tileAt` the cell under a pixel; `set` changes a
  cell; `tiles` walks the layer for marker tiles, with positions;
  `overlaps` says whether a rectangle touches a tile with a flag. New cells
  or flags can be put into a map already in use, and `restore` undoes what
  `set` changed.
  Owns: `src/maps/layers.ts`, `src/maps/layers.test.ts`. Waits on: 1.
- [x] **5. Loading and live swap.** `createMaps` keeps a console's maps by
  address. `map` parses what the generated file hands it; a file that is
  refused is reported in the console and the map stays empty. `reload` and
  `reloadFlags` fetch a changed file and swap it into every map that uses
  it, keeping the old one when the new one is refused. `restore` puts every
  map back as its file has it. The page listens for the two events.
  Owns: `src/assets/maps.ts`, `src/assets/maps.test.ts`. Waits on: 1.
- [x] **6. Generated references.** The Vite plugin writes `maps.ts` as
  under "Layout" for a project with a `maps` folder, at start and when the
  maps or sprites folders change. A map whose name, JSON or tileset cannot
  be used is left out with a warning in the terminal.
  Owns: `src/vite/maps.ts`, `src/vite/maps.test.ts`. Waits on: 1.
- [x] **7. Change events.** Saving a map file or a flags file sends its
  event to the page and stops Vite restarting the game.
  Owns: `src/vite/assets-hmr.ts`, `src/vite/assets-hmr.test.ts`.
  Waits on: 1.
- [x] **8. Demo.** The scene under "Demo": the tileset PNG, its flags, the

  Owns: `examples/07-maps/`. Waits on: 1.

## Decisions made

- **Names:** a map has its layers by name beside `columns`, `rows`,
  `width` and `height`. A layer has `draw`, `tile(column, row)`,
  `tileAt(x, y)`, `set(column, row, frame)`, `tiles(flag?)` and
  `overlaps(rect, flag)`. A tile is `{ frame, ...flags }`; one from `tiles`
  also has `x`, `y`, `column` and `row`.
- **A cell is a column and a row, two numbers; a position is pixels.**
  `tile` and `set` take a cell and nothing else, and everything that takes
  `x, y` or one value (`draw`, `tileAt`, `overlaps`) means pixels. A tile
  from `tiles` carries its pixel position as `x` and `y`, so handing it to
  a function that wanted a cell would be wrong, and the types do not
  allow it.
- **Reading a layer takes it to be drawn at 0, 0.** `draw` can put a layer
  anywhere, but `tileAt`, `tiles` and `overlaps` count from its top left.
- **`.` is an empty cell and a tile's number is its frame,** so frame 0 of
  a tileset is an ordinary tile, where Pico-8 keeps it for empty. An empty
  cell, and one outside the layer, reads as `frame: undefined` with every
  flag false.
- **`overlaps` was added** beyond the spec's `tile`: asking whether a
  hitbox touches a `solid` tile is what a game does every update.
- **Names a layer or flag cannot take:** a layer is not `columns`, `rows`,
  `width` or `height`; a flag is not `frame`, `x`, `y`, `column` or `row`.
  Both are letters and digits starting with a letter.
- **A cell is the tileset's cell size,** so a map over a 16x16 sheet has
  16x16 cells. Nothing refuses one, though the spec says tilesets are 8x8.
- **A restart puts every map back as its file has it.** `run` restores the
  maps before `init`, since `maps.ts` is not re-run by a code change and a
  tile the game took out would otherwise stay gone. Saving the map file
  also discards what `set` changed.
- **A map is whole before `init` with nothing to wait for:** its JSON is
  imported, not fetched. Only a live swap fetches.
- **`maps.ts` is written only for a project with a `maps` folder,** so the
  earlier examples get none.
- **The map and flags files are kept from Biome,** which would join a
  short layer's rows onto one line.
- **`tico8/assets` is now `src/assets/index.ts`,** exporting `sheet` and
  `map`.
- A flag name is checked against `RESERVED_FLAGS` before `NAME`, and a
  tile that is not a whole number from 0 (a string, `null`, `NaN`, a
  fraction, a negative) is refused with the same message. A tile listed
  twice under one flag is kept once.
- `mapUrl` accepts any `.json` directly in `maps/` (no subfolders, no hidden
  files), and `flagsUrl` any `*.flags.json` directly in `sprites/`. Both
  share one name encoder with `sheetUrl`, so the three addresses are spelled
  alike.
- **Map file text.** `writeMap` right-aligns every cell, `.` included, to
  one more than the width of the widest cell in any layer, and joins cells
  with one space. So a map of one-digit tiles has a space before each tile,
  as in the spec's example, and one reaching 100 has `   1` style cells,
  four wide, lined up in every layer.
- **Map file refusals.** A tile is `.` or digits only (no sign, fraction or
  exponent), up to 32767 so it fits an Int16. Messages name the layer, and
  the row counted from 1, and end without a full stop. The first layer's
  first row sets the map's columns; its row count sets the rows.
- **Loading maps.** A refused map file still gives a map with an empty
  layer for each usable name in the file, so `room1.walls.draw()` is safe.
  A refused flags file at start leaves the map without flags (`The map has
  no flags.`); refused on reload, `The old flags stay.` Only a file that
  will not load is tried a second time, not one that is read and refused.
  `load` always asks past the browser's cache, and `MapsOptions` gained
  `retryDelay`.
- **The demo's room.** `examples/07-maps/maps/room1.json` is 24 by 20
  cells (192 by 160 pixels) with layers `ground`, `walls`, `front` and
  `markers`. It uses only tiles 0 to 9, so its cells stay two wide.
- **The demo's tileset.** `sprites/tiles.png` is 8 tiles by 2: 0 floor,
  1 grass, 2 brick, 3 stone block, 4 tree trunk, 5 pillar, 6 tree canopy,
  7 arch lintel, 8 banner, 9 the spawn marker, 10 a spare crate, 11 to 15
  empty. `solid` is 2, 3, 4, 5 and 10; `spawn` is 9. Canopies, lintels and
  banners go on `front`, each canopy one cell above its trunk on `walls`.
- **The demo's collision.** The figure's sprite is its own hitbox, 8x8. Each frame it steps on x, and steps back if
  `room1.walls.overlaps(body, 'solid')`, then the same on y, so it slides
  along walls. Only `walls` is tested; `front` never blocks.
- **Layers.** `set` floors its frame, and one that cannot be a frame
  (negative, `NaN`, above 32767) empties the cell. A frame past the end of
  the tileset is kept and draws nothing. `tile` gives the same frozen
  object for the same frame until the flags change, so a game cannot write
  to one; `tiles` gives new frozen objects each call. `tiles` with a flag
  the tileset lacks gives none. `setData` copies the cells it is given, and
  a layer array shorter than `columns * rows` is padded with empty cells.
  Layers are enumerable properties of the map, in the order first seen,
  after `columns`, `rows`, `width` and `height`.
- **Generated `maps.ts`.** Imports are in Biome's own order, not plain
  alphabetical: `room2` before `room10`, `Attic` before `attic` before
  `barn`. Maps are exported in code-unit order with no blank line between
  them, as `sprites.ts`. The tileset is written `tiles,` when the sheet is
  called `tiles` and `tiles: rocks,` otherwise. A `flags` line or a
  `./sprites` import past 80 columns is broken as Biome breaks it.
- **Map names.** As sheet names, and not `map`. A map is also left out when
  its name is a tileset that `maps.ts` imports for any map; a sheet no map
  uses leaves its name free. A map whose tileset has two flags files
  (`tiles.flags.json` and `Tiles_.flags.json`) is left out, with both named.
  A flags file's ending is matched in lower case only, as `biome.json`
  matches it.

- **A sprite holds its place.** Added after the slice closed, when the
  demo had to keep a separate `body` rect and pass it to `hero.draw`. A
  sprite now has `x` and `y`, and `width` and `height` from its cell, so it
  is a rect; `hero.draw()` draws it where it is, and `sheet.sprite({ x, y })`
  starts it somewhere. `hero.draw(x, y)` stays, drawing it elsewhere without
  moving it, so the earlier examples were not ported. Example 07 lost its
  `body`.
- **No move-and-slide.** Considered and left out: `overlaps` stays a yes or
  no, and collision response is the game's own code until there is an
  opinion to build one on. Small pieces that compose are preferred here to
  a helper with behaviour baked in.

## Not checked

- A real keyboard: key events were sent by script in the browser. The
  figure started on the marker, was stopped by the wall at row 6 and slid
  along it, and the camera followed.
- Walking behind a `front` tile under its own power. A banner written
  into the figure's cell in `room1.json` while the game ran was drawn over
  it, and a block added beside it stopped it; taking 3 out of `solid` in
  the flags file let it walk through. The figure stayed where it was each
  time.
- The `maps()` plugin's watcher beyond that: adding, renaming or deleting
  a map file, or changing a map's tileset, while the dev tool runs.
- An editor that saves by writing a temporary file and renaming it over
  the map.
- A map file with `?` or `#` in its name, which Vite may read as a query.
- A map that is refused, in the browser; only tests cover the report.
- Any browser other than Chromium.
- Export (slice 13) does not exist yet; when built it has to pack maps
  and flags.
