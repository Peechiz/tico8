# 11 — UI layer

## Demo

`examples/11-ui`, a new game copied from `examples/10-save`: the star
catcher with its HUD written in JSX and styled in `ui.css`. The title is a
`<Menu>` (Start, Clear best), Ⓧ during a round opens a pause `<Menu>`
(Resume, Quit), and the end of a round shows one (Again, Title). Every
menu works with pad, keyboard and mouse, Ⓑ goes back, and the paddle does
not move and Ⓐ does not leak into the game while a menu is open.

## Spec

`01-spec.md`: Text and UI, "UI layer" and "How the UI layer works".

## Decided

- **A game's CSS is imported** from its code, as in any Vite project:
  `import './ui.css'`. Edits show without a restart.
- **The main file is `main.ts` or `main.tsx`.** The dev tool takes either;
  a game renames it when it adds a UI.
- **Palette variables are the `COLOR` names:** `var(--darkBlue)`.
- **The demo is a new example,** copied from 10-save.

## Layout

```
packages/tico8/src/ui/types.ts            UiNode, MenuProps, Nav, MenuEntry, UiLayer, CreateLayer, Rect
packages/tico8/src/ui/context.ts          NavContext: the Nav a <Menu> registers with
packages/tico8/src/ui/index.ts            `tico8/ui`: Menu, the hooks, Fragment, createContext, the types
packages/tico8/src/ui/jsx-runtime.ts      `tico8/ui/jsx-runtime`: preact's, re-exported
packages/tico8/src/ui/jsx-dev-runtime.ts  `tico8/ui/jsx-dev-runtime`: the same, for dev
packages/tico8/src/ui/menu.tsx            <Menu>
packages/tico8/src/ui/nav.ts              createNav, pick: highlight, press, back
packages/tico8/src/ui/style.ts            baseStyle: the layer's default CSS and palette variables
packages/tico8/src/ui/layer.ts            createLayer: render into the overlay, patching
packages/tico8/src/ui/font.ts             addFont: the web font as a FontFace
packages/tico8/src/ui/tico8.otf           the web font, generated
scripts/webfont.js                        writes tico8.otf from the console's FONT
packages/tico8/src/input/pad.ts           mute, raw
packages/tico8/src/host.ts                overlay: an element in game pixels over the canvas
packages/tico8/src/vite.ts                main.tsx, JSX through tico8/ui, preact prebundled
```

How the UI reaches the page: `tico8/ui` re-exports Preact, and the JSX
import source is `tico8/ui`, so a game never names Preact. The dev tool
sets that source for Vite; the workspace `tsconfig.json` sets it for the
editor (`"jsx": "react-jsx", "jsxImportSource": "tico8/ui"`).

The host wraps the canvas and puts beside it an overlay as many CSS pixels
wide and tall as the screen has game pixels, scaled by the canvas's scale
with `transform`, so one CSS pixel is one game pixel. The layer renders
into it. The overlay ignores the pointer, so the game's mouse still reads
the canvas, except on what can be pressed: `button`, `a`, `input`,
`select`, `textarea`, `[tabindex]`.

One update, as `run` drives it:

```
pad.sample()
pad.mute(nav.active)   a <Menu> on screen: the game's input reads as idle
nav.step(pad.raw)      directions move the highlight, Ⓐ clicks, Ⓑ calls onBack
game.update()
layer.render(game.ui())
```

A menu opened by one render mutes from the next update; a click that
closes it still leaves that update muted, and after it a button still held
reads `held` but not `pressed`, so the Ⓐ that chose Resume never reaches
the game.

The layer's default CSS sits in `@layer tico8`, so any game CSS beats it
whatever its specificity. It sets each palette colour as a variable on the
overlay, the font (`font: 6px/6px tico8`), the text colour (the palette's
lightest), buttons that inherit font and colour with no border, background
or padding, and the highlight: a 1 px outline in the current colour on the
focused element.

The highlight is the browser's focus. A menu focuses its first enabled
button when it opens; the pointer moving over a button of the top menu
focuses it. A direction moves focus to the nearest focusable element in
the top menu that way, by the boxes' centres; with none that way it stays.
A direction held does not repeat.

The web font is the console's `FONT` drawn as squares: 100 units a pixel,
600 to the em, ascent 500, descent 100, each glyph as wide as its pixels
plus the spacing. At `6px` a font pixel is a CSS pixel.
